# SPK web parity discovery for Webhooks

Source review of [SPK web `acf2a89`](https://github.com/meeehdi-dev/spk/commit/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c) and [SPK desktop `2cd9787`](https://github.com/ChristopheCVB/spk-gpui/commit/2cd9787b964e98b7b7f3f7be13d4d7444e304040). The web revision includes GitHub event formatting. Neither client nor an SPK deployment was run.

## Web workflow

- **Webhooks** is a sidebar section below Voice Channels. It has a **New webhook** button for every signed-in user, a **No webhooks yet** empty state, and a row per visible feed with its name, icon, unread count and a lock for private feeds. Feeds are also available in the Quick Switcher and sidebar keyboard navigation. The row menu offers **Mark read**, **Mute notifications** and **Copy link**. Muting dims the row and keeps the unread badge. The copied link opens the feed inside SPK. [Sidebar](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/app/components/AppSidebar.vue#L341-L377) · [Row menu](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/app/components/AppSidebar.vue#L43-L68) · [Sidebar navigation](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/app/composables/useUnread.ts#L60-L69) · [Quick Switcher](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/app/components/QuickSwitcher.vue#L19-L25)
- A **webhook feed** is a read-only history of **alerts** posted by external services using its **Webhook URL**. Create and Edit use a name, a Lucide icon and a Private toggle. Creation starts private in the web form, then opens the new feed and displays the URL with a Copy button. **New secret URL** requires confirmation, immediately invalidates the previous URL and displays the replacement once. **Delete** requires confirmation and removes the feed and all its alerts for everyone. The API stores a hash of the secret and returns the URL only after creation or rotation. [Dialog](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/app/components/WebhookDialog.vue#L12-L119) · [Storage and mutations](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/server/db/webhooks.ts#L12-L87)
- A private feed is visible and manageable only by its owner, including when someone else is an Admin. A public feed is visible to all signed-in users, and its owner or an Admin can edit, rotate, or delete it. A non-owner Admin who switches a public feed to private also loses access, since ownership remains with the creator. The same audience applies to history and live alerts. [Management permissions](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/server/db/webhooks.ts#L24-L70) · [Readable channels and WebSocket audience](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/server/db/messages.ts#L85-L115)
- The feed uses the normal chat history, with **No alerts yet** for an empty feed and a **Read-only feed** label in place of the composer. Alerts show the feed name and icon as the author. Users can copy text, Markdown, or a permalink and mark an alert unread. The owner and any Admin with access can delete an alert. Replying, editing, quoting, reacting and pinning are unavailable. [Empty state and alerts](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/app/components/chat/ChannelView.vue#L495-L534) · [Read-only footer](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/app/components/chat/ChannelView.vue#L565-L583) · [Alert actions](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/app/components/chat/ChatMessage.vue#L134-L196) · [Alert author](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/app/components/chat/ChatMessage.vue#L271-L306) · [Pin permissions](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/shared/utils/pins.ts) · [Server delete permissions](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/server/db/messages.ts#L377-L395)

## Server contract

| Operation | Contract |
| --- | --- |
| List | `GET /api/channels` includes visible rows with `id`, `type: "webhook"`, `name`, `icon`, `ownerId`, and `private`, ordered by creation time within the section. [Channel DTO and list](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/server/db/dms.ts#L53-L91) |
| Create | `POST /api/webhooks` accepts `{name, icon, private}` and returns `{channel, url}`. The API treats only literal `true` as private, so the client supplies that value explicitly. The server cleans and checks the name at 1–32 characters and validates Lucide-style icon names. [Create route](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/server/api/webhooks/index.post.ts) · [Create logic](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/server/db/webhooks.ts#L29-L42) · [Name and icon validation](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/server/db/sounds.ts#L14-L20) |
| Edit, rotate, or delete | `PATCH /api/webhooks/{id}` returns the updated channel. `POST /api/webhooks/{id}/secret` returns `{url}`. `DELETE /api/webhooks/{id}` returns `{ok: true}`. All four management routes broadcast `channels:changed` for clients to refresh the channel list. [Edit route](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/server/api/webhooks/%5Bid%5D.patch.ts) · [Rotation route](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/server/api/webhooks/%5Bid%5D/secret.post.ts) · [Delete route](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/server/api/webhooks/%5Bid%5D.delete.ts) |
| Receive an alert | An external service posts to the generated Webhook URL. The SPK server validates it, formats the incoming payload and publishes the result as a normal `message:new` followed by `unread:update` to the permitted audience. Successful deliveries and intentionally skipped events both return `204`. [Ingest route](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/server/api/hooks/%5Bid%5D/%5Bsecret%5D.post.ts) · [Message fanout](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/server/utils/chat.ts#L27-L40) |

Alerts can be plain text, an embed, or both. The server normalizes Discord-style, Slack-style, generic JSON, and GitHub event payloads and strips mention tokens. GitHub events such as pushes, pull requests, issues and completed workflow runs produce cards. The server skips some events, including individual CI job updates. A card can have a linked title, Markdown description, status color, inline or full-width fields, footer and timestamp. An alert can have an empty message body when it has a card. [Payload formatting](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/server/utils/webhookPayload.ts#L137-L168) · [GitHub event formatting](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/server/utils/githubPayload.ts) · [Embed schema](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/shared/utils/embed.ts) · [Card rendering](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/app/components/chat/WebhookEmbed.vue#L14-L33) · [Empty message validation](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/server/db/messages.ts#L248-L258)

Unread counts include alerts from your own webhook, even though the message DTO carries your user ID. Web shows unread indicators without foreground or push notifications. Search includes readable feeds in **Everything** and in the active feed’s scope. Keyword results use the message body, so a term that appears only inside a rich embed does not match. The server prunes alerts older than 30 days. ## Desktop starting point

A channel list with zero webhook rows is consistent with both an older server and a supported server where the user has zero visible feeds. The pinned channel list has no capability field and the health endpoint only reports database availability. [Channel list](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/server/api/channels/index.get.ts) · [Health endpoint](https://github.com/meeehdi-dev/spk/blob/acf2a89b3ed8923b950fb87488ca3b41afc6ca8c/server/api/health.get.ts)

The desktop channel DTO accepts a string kind, so `webhook` rows can coexist with existing rows in an API response. The conversation predicate only accepts text and DMs, and the DTO lacks the feed’s owner, icon, and privacy fields. The message DTO also lacks the optional embed. Desktop already fetches conversation history, performs channel refreshes on `channels:changed` and closes a selected text channel when a refreshed list omits it. The Soundboard settings have a searchable bundled icon picker.
