## Verification by platform

| Platform | Existing evidence | Remaining evidence |
| --- | --- | --- |
| macOS | Apple Silicon microphone permission code was type-checked. A later CI run passed tests and debug build on macOS 15, plus development-bundle signature verification. | A pinned native run with physical devices and an independent web client, including live input switching with AirPods and built-in or wired devices. |
| Windows | Earlier Windows 11 locked build and local LiveKit capture/playback evidence, plus a user confirmation that the rebuilt app worked on the configured deployment. Later Windows Server 2022 CI passed tests and build. | Full physical-device and recovery checklist with documented versions, devices and outcomes on the pinned baseline. |
| Linux | WSL2 with virtual PulseAudio exchanged audio with a Chromium peer using a loopback SPK fixture. Native Ubuntu 24.04 CI passed tests and build. | Native Linux desktop run with physical devices and an independent web client against an existing SPK Instance. |

Phase 5 records the physical-device checks as pending across all three platforms. The verification issue is closed, with unchecked acceptance criteria and no result comment. This audit found no complete hardware record for the pinned pair and ran no sessions itself. The roadmap needs to decide the native capture and playback acceptance criteria for Camera, Screen Share, and Media Output after the voice milestone is verified. Platform behavior for capture sources and screen audio needs evidence before choosing parity compromises.
