## Integration and acceptance questions

- Use web and desktop accounts in the same Text Channel and in a DM Conversation. Confirm the same history, real-time sends, edits, deletes, Reactions, pins and read points. The web groups history and pin reads under channel IDs, creates DMs with the dedicated HTTP endpoint and uses the authenticated socket for live messages. [Web message lifecycle](https://github.com/meeehdi-dev/spk/blob/f23de3c687303bb87e4c53ce212fef7ee41f5a62/app/components/chat/ChannelView.vue) · [DM endpoint](https://github.com/meeehdi-dev/spk/blob/f23de3c687303bb87e4c53ce212fef7ee41f5a62/server/api/dms/index.post.ts) · [SPK socket route](https://github.com/meeehdi-dev/spk/blob/f23de3c687303bb87e4c53ce212fef7ee41f5a62/server/routes/_ws.ts)
- Decide how native notification delivery and deep links behave with the app focused, unfocused, or closed. Web Push is a browser delivery mechanism. The user-visible acceptance criteria should cover preference changes, suppression, and opening the correct conversation or message. [Web foreground behavior](https://github.com/meeehdi-dev/spk/blob/f23de3c687303bb87e4c53ce212fef7ee41f5a62/app/composables/useNotify.ts) · [Web background delivery](https://github.com/meeehdi-dev/spk/blob/f23de3c687303bb87e4c53ce212fef7ee41f5a62/app/composables/usePush.ts)
- Preserve feature gating for configured services and server-side permissions, including access to attachments and DM content. [Attachment access](https://github.com/meeehdi-dev/spk/blob/f23de3c687303bb87e4c53ce212fef7ee41f5a62/server/api/attachments/[id].get.ts) · [GIF endpoint](https://github.com/meeehdi-dev/spk/blob/f23de3c687303bb87e4c53ce212fef7ee41f5a62/server/api/gifs/index.get.ts) · [Search access](https://github.com/meeehdi-dev/spk/blob/f23de3c687303bb87e4c53ce212fef7ee41f5a62/server/api/search.get.ts)

## Verification by platform

On macOS, Windows, and native Linux, the pinned desktop exposes the same source-level messaging inventory above. The audit found no desktop messaging runtime tests. It did not launch either client. The documented cross-platform CI runs cover build and tests, and the prior end-to-end evidence covers voice and sign-in.
