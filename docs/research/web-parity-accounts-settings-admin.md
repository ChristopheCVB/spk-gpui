## Verification by platform

- **macOS:** Previous records include a native development-bundle launch and signature checks. The full account and Settings comparison was source-only. [Launch evidence](https://github.com/ChristopheCVB/spk-gpui/blob/3685614a758f41efefb13dea9444e26a77bd0077/docs/PHASE-1.md) · [CI evidence](https://github.com/ChristopheCVB/spk-gpui/blob/3685614a758f41efefb13dea9444e26a77bd0077/docs/PHASE-5.md)
- **Windows:** Previous records cover native builds and a working session on the configured deployment. Recheck session restoration and cleanup for the pinned revisions alongside any new account flows. [Authentication checks](https://github.com/ChristopheCVB/spk-gpui/blob/3685614a758f41efefb13dea9444e26a77bd0077/docs/PHASE-2.md) · [Deployment result](https://github.com/ChristopheCVB/spk-gpui/blob/3685614a758f41efefb13dea9444e26a77bd0077/docs/PHASE-3.md)
- **Linux:** Previous records include WSL2 integration checks and native Ubuntu CI build and tests. Native desktop session restoration needs a working Secret Service provider and a verified launch environment. [Linux prerequisites](https://github.com/ChristopheCVB/spk-gpui/blob/3685614a758f41efefb13dea9444e26a77bd0077/README.md) · [Session tests](https://github.com/ChristopheCVB/spk-gpui/blob/3685614a758f41efefb13dea9444e26a77bd0077/docs/PHASE-2.md) · [CI evidence](https://github.com/ChristopheCVB/spk-gpui/blob/3685614a758f41efefb13dea9444e26a77bd0077/docs/PHASE-5.md)

The audit did not launch either client. Its roadmap input is to preserve existing-account sign-in while defining what a desktop user should experience when opening invite, reset, and message links. For Admin workflows, acceptance should exercise the same operations with an Admin and a User account and confirm server-side authorization and web-visible updates.
