# Domain docs

## Before exploring

- Read the root `GLOSSARY.md` for project vocabulary.
- Read the ADRs in `docs/adr/` that apply to the area you are working in.

This repository uses a single domain context. If these files are absent, continue with the repository's existing documentation. The `domain-modeling` skill creates a glossary or ADR when a domain term or decision is resolved.

## Use the glossary's vocabulary

Use the glossary's terms in issues, refactor proposals, and tests. If the code uses an undefined term, surface it during domain modeling.

## Flag ADR conflicts

If a proposal conflicts with an existing ADR, name the ADR and describe the conflict.
